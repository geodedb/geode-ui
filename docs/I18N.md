# i18n discipline

Geode UI uses [i18next](https://www.i18next.com/) +
[react-i18next](https://react.i18next.com/). The configuration deliberately
disables i18next's own value-escaping (`escapeValue: false` at
`src/services/i18n/config.ts`) because React already escapes interpolated
text at render time. That choice is **safe under one rule**: every
translated value must reach the DOM through a React text node or a known
attribute, never through a JSX HTML renderer.

This document records the rule, the reason, the pre-commit gate that
enforces it, and the escape hatch when an exception is genuinely needed.

## The rule

> **Never feed a `t()` value through the JSX `__html` prop, and never
> introduce `<Trans>` without an explicit `components` allowlist.**

If you are tempted to write either of these, a translated value is going
to render as raw HTML at the user's browser. With `escapeValue: false`,
that means an attacker who can influence a translation key (a stored
copy, a forked locale, a future translation-management UI) gets a
stored-XSS sink for free.

## The reason

The default i18next setting (`escapeValue: true`) double-escapes against
React's escape, mangling ampersands and quote characters inside the
translation string. The cure is worse than the disease for an app that
funnels every value through React text. So we set `escapeValue: false`
and rely on React's escape — *but only for text*. The two JSX patterns
below skip React's escape:

1. `<X dangerouslySetInnerHTML={{ __html: value }} />` — the prop's name
   is React's warning to you. The HTML is parsed and inserted; whatever
   tags are in `value` become DOM.
2. `<Trans i18nKey="…" />` — the component renders the translation
   *as JSX*, including HTML tags inside the translation string. Without
   an explicit `components` map, every tag in the translation goes
   through unescaped.

Both render attacker-influenced strings as markup. With our config,
both turn the i18n boundary into an XSS sink.

## The gate

`scripts/check-html-renderers.mjs` (run from `pnpm check:html-renderers`)
greps `src/**/*.{ts,tsx}` for the two patterns. The gate is wired at
`.pre-commit-config.yaml` and runs on every commit. Zero hits at land
time, strict mode from day one.

If your change introduces one of the patterns intentionally and the
reviewer has signed off on the risk, suppress the gate per-line:

```tsx
// eslint-disable-next-line html-renderer
<Trans i18nKey="rich.welcome" components={{ b: <strong /> }} />
```

The `// eslint-disable-next-line html-renderer` annotation is recognised
by the script (it isn't an actual ESLint rule today; the comment is a
shared spelling so the convention survives if we move enforcement to a
custom ESLint rule later).

## Adding a new locale

1. Copy `src/services/i18n/locales/en.ts` to `src/services/i18n/locales/<bcp47>.ts`.
2. Translate values; **preserve `{{var}}` placeholders verbatim**.
3. Add the new code to `SUPPORTED_LANGUAGES` and `RESOURCES` in
   `src/services/i18n/locales/index.ts`.
4. Run `pnpm verify:translations` — it parses every `t('key')` site in
   `src/` and confirms the key resolves in every required locale (default:
   `en`). Zero missing, zero orphan today; the gate fails the commit
   otherwise.
5. Run `pnpm check:html-renderers` to confirm no translator-introduced
   `<b>`/`<i>` markup leaked into the values (you can include them in
   text, but if you intend them as markup, you must use `<Trans>` with
   an explicit `components` allowlist — see "The gate" above).

## Plurals and interpolation

i18next conventions:

- Plural forms: `key_one`, `key_other`, `key_few`, `key_many`, `key_zero`.
  Call as `t('key', { count: n })` — the validator treats the suffixes
  as alternate declarations of the base key.
- Variables: `'Hello {{name}}'` rendered with `t('greet', { name })`.
- Date and number formatting goes through
  `useLocalization().formatDate / formatNumber / formatRelativeTime`,
  not through translation strings.

## Where the audit ratchets sit

| Script | Stage | Closes |
|---|---|---|
| `verify:translations`     | pre-commit + CI | Every `t('key')` resolves in `en` |
| `detect:hardcoded-strings`| pre-commit + CI | New JSX `label`/`placeholder`/`aria-label` literals |
| `check:html-renderers`    | pre-commit + CI | This document's rule (Q-NEW-2 / S-NEW-3) |
