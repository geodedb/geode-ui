## Scope

This document tracks performance findings for the **geode-ui** repository, which contains both:

- **Backend** (Go): HTTP/WS query gateway in `internal/server/`, connection pool in `internal/conn/`, server entrypoint in `cmd/server/`. Code is generated by `genapi` (do not hand-edit `gen/`).
- **Frontend** (React + TypeScript): Vite-built SPA under `src/`. Major consumers: Monaco editor (`src/pages/QueryPage.tsx`), Cytoscape graph view (`src/components/results/GraphView.tsx`), result table (`src/components/results/TableView.tsx`).

Findings cover hot paths in: REST query, WebSocket streaming query, table rendering, graph rendering, schema explorer, audit polling, server hygiene, driver layer.

## Assumed workload

No SLOs are documented in the repo. Phase 3 inferred a working assumption:

- **Steady state**: ~2,000 rps on `/api/v1/query` (mix of cheap auth/schema reads and user-issued GQL).
- **Burst**: ~400 concurrent users issuing simultaneous queries (admin dashboards refreshing).
- **Result-set distribution**: 10th-90th percentile = 1-1,000 rows; tail to 100k+ rows on streamed `MATCH (n)` queries.
- **Query latency p50**: ~10 ms upstream (Geode driver over QUIC).

These assumptions are the basis for sizing recommendations (e.g., F11 pool sizing). Replace with measured SLOs once they exist.

### db — Driver / connection pool

- **F11 (#55)** — Pool defaults 16/4 too small for 2,000 rps assumption.
- **F18 (#61)** — **Won't-do (2026-05-11).** Hypothesis was: the driver re-parses identical parameterised statements, so an LRU `*sql.Stmt` cache in `pool.go` would amortise that parse. Benchmark `internal/conn/pool_bench_test.go` (`BenchmarkParseVsExecute`, `BenchmarkParseFraction`) refutes the premise: (1) parse is ~10% of a modelled round-trip — under the ~20% threshold the AC set for landing the cache; and (2) more decisively, the geode driver has **no server-side prepared statements** — `geode.Conn.PrepareContext` does no round-trip and just stashes the query text, and `geode.Stmt.QueryContext` re-sends that text via `conn.QueryContext(ctx, s.query, args)`, i.e. the server re-parses on every call regardless of whether a `*sql.Stmt` was used. So a stmt cache has nothing to amortise. Bench numbers: `PerQueryContext` ≈ 85–107 µs/op vs `PreparedStmtReuse` ≈ 96–107 µs/op (within noise; `PreparedStmtReuse` carries 2 extra allocs/op from the `database/sql` Stmt machinery). Re-open only if the geode driver gains real server-side prepare/parse-cache support.

## Notable absences

The following capabilities are NOT present in the repo as of this audit. Each is a structural gap, not a single bug:

- **No virtualization** anywhere in the result UI — `TableView` mounts every TR (F5).
- **No streaming JSON** in the REST query handler — entire body buffered before first byte (F3).
- **No `sync.Pool`** for jsontext buffers, scratch row slices, or marshal byte buffers (F13, partly F1/F2).
- **No HTTP compression** (gzip/zstd) on JSON responses (F13).
- **No `net/http/pprof`** mount on any port; live diagnostics require a custom build (F13).
- **No documented SLOs** — every sizing decision (e.g., F11) is inferred. Document target rps / p99 latency / max stream duration so subsequent perf work has a target.
- **No CI perf gate** — no benchmark suite is enforced in CI; regressions on the codec, pool, or table render path will not be caught automatically. Consider adding `go test -bench` smoke + a frontend Lighthouse budget once baseline is established.
- **No prepared-statement cache** in the driver layer — investigated under F18 and closed won't-do 2026-05-11: the geode driver has no server-side prepared statements, so there is nothing for a `*sql.Stmt` cache to amortise (benchmark in `internal/conn/pool_bench_test.go`).
- **No frame-batching protocol** on WS — wire-protocol change required to bundle rows (F2).

### EPIC: `epic::secure-store-coalescing`

Anchor issue: **[PSR-F6 / #92](https://gitlab.com/devnw/codepros/geode/geode-ui/-/work_items/92)** — secure-store full file decrypt+re-encrypt per IPC.

The four issues below MUST ship together as a single MR. They overlap on the same hot path (modal-open + typing + reducer ticks). Fixing the renderer hot loops without coalescing the main-process secure store, or vice versa, leaves most of the cost on the floor:

| F-ID | Issue | Layer | Role in epic |
|------|-------|-------|--------------|
| PSR-F6 | [#92](https://gitlab.com/devnw/codepros/geode/geode-ui/-/work_items/92) | Electron main | In-process memo + write coalescer (anchor) |
| PSR-F9 | [#106](https://gitlab.com/devnw/codepros/geode/geode-ui/-/work_items/106) | Renderer | Reducer-tick effect → version-int dep |
| PSR-F13 | [#110](https://gitlab.com/devnw/codepros/geode/geode-ui/-/work_items/110) | Renderer | Collapse 4 modal-open useEffects + gate saved-creds |
| PSR-F14 | [#111](https://gitlab.com/devnw/codepros/geode/geode-ui/-/work_items/111) | Renderer + Electron | Debounce + renderer-side decrypted-password cache |

**Rationale for shipping together**: F6 alone produces a coalesced cache the renderer never warms efficiently. F9/F13/F14 alone reduce IPC volume but every remaining IPC still triggers a full file round-trip. The win is multiplicative; only the joint MR clears the per-modal IPC + disk cost.

**Closed 2026-05-10** in a single MR (`fix: close GAP-perf-secure-store - coalesce writes, gate password lookups, version-keyed persist effect`). Representative reductions:

- **Modal-open + 5-keystroke username (toggle OFF — typical first-login)**: pre-fix 5 IPCs × full safeStorage decrypt round-trip; post-fix 0 IPCs (toggle gates the lookup entirely).
- **Modal-open + 5-keystroke username (toggle ON, no cache hit)**: pre-fix 5 decrypts + 5 reads; post-fix 1 decrypt at the end of the 300ms idle window (memo serves any subsequent re-type for free).
- **5 sequential `add` dispatches in the connections reducer** (e.g. hydrating from disk + 4 connectMore calls): pre-fix 5 IPCs × 5 file rewrites = 5 encrypts + 5 atomic renames; post-fix 5 IPCs (one per real version bump) collapse into 1 encrypt + 1 atomic rename via the F6 debounce window.
- **Reducer no-op transitions** (re-add identical payload, `setActive` to current id, `remove` of unknown id): pre-fix N IPCs; post-fix 0 IPCs (no version bump).
