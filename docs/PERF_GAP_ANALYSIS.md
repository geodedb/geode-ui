## Scope

This document tracks performance findings for the **geode-ui** repository, which contains both:

- **Backend** (Go): HTTP/WS query gateway in `internal/server/`, connection pool in `internal/conn/`, server entrypoint in `cmd/server/`. Code is generated by `genapi` (do not hand-edit `gen/`).
- **Frontend** (React + TypeScript): Vite-built SPA under `src/`. Major consumers: Monaco editor (`src/pages/QueryPage.tsx`), Cytoscape graph view (`src/components/results/GraphView.tsx`), result table (`src/components/results/TableView.tsx`).

Findings cover hot paths in: REST query, WebSocket streaming query, table rendering, graph rendering, schema explorer, audit polling, server hygiene, driver layer.

## Assumed workload

No SLOs are documented in the repo. Phase 3 inferred a working assumption:

- **Steady state**: ~2,000 rps on `/api/v1/query` (mix of cheap auth/schema reads and user-issued GQL).
- **Burst**: ~400 concurrent users issuing simultaneous queries (admin dashboards refreshing).
- **Result-set distribution**: 10th-90th percentile = 1-1,000 rows; tail to 100k+ rows on streamed `MATCH (n)` queries.
- **Query latency p50**: ~10 ms upstream (Geode driver over QUIC).

These assumptions are the basis for sizing recommendations (e.g., F11 pool sizing). Replace with measured SLOs once they exist.

## Quick wins (combined plays)

The three quick-win plays bundle related findings into single PRs to amortize review and rollout cost. All quick-win issues carry the `perf::quick-win` label on GitLab.

1. **Frontend table quick-win (#26)** — `F4 + F5 + F6` in one PR.
   - Mutable-ref row reducer + `react-window` virtualization + memoized `projectColumns(resp)`.
   - **Expected gain**: 1000-row render goes from ~2s + tab freeze to <250 ms first paint; p99 frame time <16 ms during 5k-row stream.
   - Touches: `src/pages/QueryPage.tsx`, `src/components/results/TableView.tsx`. New dep: `react-window` (~6 KB gz).

2. **Server config quick-win (#55 + #56)** — `F11 + F12` in one ops/config PR.
   - Bump pool to 64/16 with env override + remove WriteTimeout on `/ws/*` (per-route) + add per-frame WS deadlines.
   - **Expected gain**: p99 latency reduction at 2000 rps (no pool queueing); WS streams >60s no longer killed; same-burst throughput uncapped.
   - Touches: `internal/conn/pool.go`, `cmd/server/main.go`, `internal/server/ws_query.go`.

3. **Graph render quick-win (#53)** — `F9` standalone but small.
   - Gate Cytoscape rebuild on `resp.status === 'done'` (or `resp.row_count` change at done time).
   - **Expected gain**: layout invocations drop from N (one per streamed row) to 1; eliminates tab freeze on graph queries.
   - Touches: `src/components/results/GraphView.tsx`.

Together these three plays clear all P0 findings and the highest-impact P1 findings with three small, independently-shippable PRs.

## Notable absences

The following capabilities are NOT present in the repo as of this audit. Each is a structural gap, not a single bug:

- **No virtualization** anywhere in the result UI — `TableView` mounts every TR (F5).
- **No streaming JSON** in the REST query handler — entire body buffered before first byte (F3).
- **No `sync.Pool`** for jsontext buffers, scratch row slices, or marshal byte buffers (F13, partly F1/F2).
- **No HTTP compression** (gzip/zstd) on JSON responses (F13).
- **No `net/http/pprof`** mount on any port; live diagnostics require a custom build (F13).
- **No documented SLOs** — every sizing decision (e.g., F11) is inferred. Document target rps / p99 latency / max stream duration so subsequent perf work has a target.
- **No CI perf gate** — no benchmark suite is enforced in CI; regressions on the codec, pool, or table render path will not be caught automatically. Consider adding `go test -bench` smoke + a frontend Lighthouse budget once baseline is established.
- **No prepared-statement cache** in the driver layer (F18, suspected).
- **No frame-batching protocol** on WS — wire-protocol change required to bundle rows (F2).

Anchor issue: **[PSR-F6 / #92](https://gitlab.com/devnw/codepros/geode/geode-ui/-/work_items/92)** — secure-store full file decrypt+re-encrypt per IPC.
